# AI, chat, swarm and generation audit — 5 September 2026

## Evidence and scope

Reviewed the AI stage reviews, draft enhancement helpers, owner swarm, accelerated pipeline, conversational intake, application/inspector export, certificate/retraction rendering, proposal generation, resource PDF/DOCX export, and certificate backup scheduler. Changes are implemented locally and integrated with the backend worker's transactional draft writes and explicit human decision provenance. This report does not establish production deployment, regulatory registration, clinical validation, independent penetration testing, or operational accreditation.

## Critical issues fixed

- Removed the automated final approval/certificate pathway. Previously a presence/length heuristic or fictional named bot votes could set an application to approved and issue an IRB number. Automated checks now create advisory findings and route to a qualified human committee. The legacy approval helper also blocks issuance so old callers cannot silently bypass the boundary.
- Removed the invented 510-expert panel claims. Each panel runs six actual model domain analyses plus a synthesis. Reported counts are six model analyses, with one strict machine recommendation per domain. Invalid or inflated tallies make a report unavailable; they are never normalized into an approval quorum. Different prompts are not evidence of model independence or calibrated medical accuracy.
- Removed forced positive answers claiming official NCBE licensing/accreditation. English and Arabic chat answers now ask for verifiable institutional evidence. Chat cannot approve research, issue credentials, or represent an unverified institution.
- Applicant titles and narratives no longer become system instructions. Draft and model report data uses unique per-block delimiters; chat uses server-owned conversation history and ignores forged client assistant messages. This is defense in depth, not a claim that prompt injection is solved.
- AI review parsing now rejects missing, nested, nonnumeric, nonfinite, duplicate, and incomplete assessments. Critical field scores force the red-flag result, independently of the model's flag. Required fields containing generated missing-information or assumption markers cannot pass.
- Draft-generation results use known field allowlists and bounded strings. Unknown fields, status, approvals, ownership, and certificate fields cannot cross the generation boundary. Stage 1 enhancement preserves investigator/institution/funding facts. Missing evidence remains explicitly marked.
- Chat edits apply only to editable applications through a row-locked, ownership-checked, stale-snapshot-checked backend write. A changed draft invalidates previous AI passes and scores. Submitted, approved, retracted, and review-locked records remain unchanged. Provider failure returns an unavailable result, without claiming successful field updates. Secret-like output is redacted, and input/history/output sizes are bounded.

## Document correctness and confidentiality

- Replaced sample-text substitution in certificates with a single-pass explicit-token template. The real research title appears, HTML is escaped, and applicant text that resembles template tokens cannot cause recursive substitution.
- Approved/retracted decision records require a recorded IRB number, valid approval date, and explicit human decision provenance (`humanDecisionByUserId`, `humanDecisionAt`). Legacy automated approvals require committee reassessment; the new migration deliberately does not attest them retroactively.
- Rejection and retraction are distinct notices. They never say the research is approved/active. Missing approval dates remain not applicable. No one-year expiry, handwritten signature, official government status, or named approving authority is fabricated.
- HTML/PDF/DOCX share decision status, research details, source dates, verification link, and limitations. Public copies omit account name/email, department, funding, internal scores, and sensitive rejection/retraction reasons. Public certificate downloads regenerate the redacted current decision using the IRB number and provenance; they do not expose a private stored PDF URL.
- QR generation must succeed; no decorative placeholder is presented as a scannable verification code. Production generation requires a configured canonical HTTPS site origin. Browser rendering disables JavaScript/service workers, blocks network requests, reuses browser instances, and uses the shared bounded render semaphore. Certificates return correctly labelled printable HTML if Chromium is unavailable; template PDF generation requires Chromium.
- Confidential export responses use no-store, noindex, no-referrer, nosniff and sandbox CSP. Template generation requires authentication and bounded typed answers; integer IDs are strict. Applicant application exports omit internal raw audit details. ZIP streams handle errors/disconnects and use moderate compression. CSV formula prefixes are neutralized. Checksums are described as checksums, not an independent signature/authenticity guarantee.
- Proposal exports are visibly marked draft, with the actual AI-assisted versus source-only fallback mode. Absent budgets, time commitments, team members, citations, literature evidence, and compliance conclusions are no longer invented. Protocol methods/consent/data security facts remain copied from the applicant's source fields, with unknowns marked for verification. Only a bounded narrative subset is AI-assisted.
- Backup directories/files use restricted modes; snapshots skip symlinks, date pruning rejects impossible dates, and daily jobs do not overlap. Object storage copies still require a configured lifecycle policy to enforce retention remotely.

## Remaining launch requirements

- Verify and document the operating institution, local committee registration/authority, actual human reviewers, conflicts, decision conditions, validity/renewal policy and human signature workflow. The code does not create regulatory authority. Configure the real domain before public certificate issuance. Global use in 2027 needs jurisdiction-specific policy and approval authority, not a date-based software switch.
- Complete processor contracts, lawful sensitive-data handling and cross-border/residency review for each LLM and literature source. This audit did not send real participant data or verify a provider's regional retention policy. The application still allows free text, so prompt defenses and secret regexes are not complete DLP. Patient identifiers should not be entered in protocol chat; production needs evaluated content controls and incident escalation.
- Calibrate AI reviews against representative Arabic/English protocols and independently adjudicated reference cases, including bias, uncertainty, injection, refusal and non-fabrication evaluations. Multiple calls are advisory perspectives, not independent experts. Human final authority remains mandatory.
- Configure encrypted production backups and object lifecycle retention, perform a restoration drill, verify the deployment image's Chromium/font dependencies, exercise all templates with long multilingual real-world content, and run operational load/failure tests in the actual production topology. Local test success does not certify public operational capacity.
