# Backend workflow, authorization, storage and integrity audit

Audit scope: the complete application router, database helpers and schema, REST/MCP adapter, storage backends, readiness validation and committee enrollment. Verification used synthetic fixtures in an isolated local MySQL instance; no production records or external integrations were accessed or mutated, and no production credentials were inspected or disclosed.

## Material changes

- **Human decision authority:** removed automatic appointment of administrators and simulated reviewers. An active seat now requires a recorded qualification/appointment reference, appointing user and appointment date. Legacy automated seats do not qualify. Final approval/rejection requires an independent appointed human administrator; self-decision is blocked. Approval additionally requires institutional issuance activation and independent human votes. The compatibility direct-approval endpoint uses the same gates; it cannot approve a draft or bypass human review.
- **Issuance evidence:** `IRB_ISSUANCE_ENABLED=true` must be explicitly configured before approvals are issued. Every new human decision records `humanDecisionByUserId` and `humanDecisionAt`. Legacy terminal records are preserved but excluded from public verification/registry and official certificate generation until their authority is established. Nullable migration fields do not silently validate old AI decisions.
- **Transactional state integrity:** submission locks the parent application and atomically commits its state, assignments, workload counters, audit and immutable submission snapshot. Concurrent duplicate submissions cannot create duplicate assignment sets or versions. Prior-round votes expire before a revised protocol is submitted. Reviewer votes and counters commit once; a late vote cannot reopen a terminal application. Final decisions serialize on the application and cannot be replayed. Generated certificates attach only to the exact decision/submission that produced them.
- **Editing and document integrity:** draft edits serialize with submission. A changed gateway/protocol clears obsolete AI passes, scores, feedback and override flags. A stale AI result is rejected if the application changed while the model worked. Applicant author changes and uploads cannot modify a submitted/terminal record. Co-investigator, draft and upload allowances are enforced within database transactions. Accepted uploaded references must belong to the submitting account and application; arbitrary external or another account's documents are rejected.
- **Private data:** user search now strips password hashes, and `auth.me` explicitly omits the hash regardless of its source. Public registry records contain neither internal application IDs nor stored private certificate URLs. Public download requests use the redacted export route instead of signing an internal PDF. Free-form retraction reasons are not disclosed in public verification. Inactive/unappointed/expired reviewers lose application access. Nonowner staff access is subject to the signed MFA assertion supplied by the authentication layer.
- **Storage:** new uploaded-file links are stable authenticated `/api/irb/files/:id` routes with private/no-store caching. An authorized request refreshes a short storage redirect. S3 URLs default to 300 seconds and are capped at 900 seconds; writes request encryption at rest. Ambiguous/traversal/dotfile keys are rejected, local file/directory modes are restrictive, and `UPLOADS_DIR` supports an isolated durable volume. Configured cloud storage failures never downgrade silently to local disk. Production local storage requires `ALLOW_LOCAL_STORAGE=true`. Metadata persistence failures do not report an upload success. MIME signatures, filename extensions, canonical base64 and decoded size limits are checked; executable extensions cannot be smuggled through a ZIP MIME label.
- **Account authority and logout:** unverified email claims cannot bootstrap an administrator. Native registration always creates a user. Logout waits for durable session revocation before clearing the cookie; a revocation outage returns an unavailable error and never claims success.
- **Safety operations:** serious adverse events persist as escalated, and future occurrence dates are rejected. Amendment decisions require an independent appointed human authority, an active parent and institutional activation, and cannot be replayed. Annual continuing-review reminders are committed with their audit and deduplicated for seven days, including concurrent operators. Reminders do not purport to renew a study or establish an institution's legally binding expiry period.
- **API/MCP:** the only mutating MCP endpoint is `/api/mcp`, behind API origin/rate guards. The unguarded `/mcp` alias was removed. Requests validate JSON-RPC structure and bounded integer application IDs, support initialization/ping/initialization notifications, scope tools by role, and preserve MCP error envelopes without disclosing internal exceptions. Mutating notifications without request IDs never execute. REST file download authorization is independently tested.
- **Operational evidence:** unavailable public statistics, registry data and owner telemetry return unavailable errors, rather than manufactured zero counts. Unobserved processing/dwell averages remain null. Application statistics use one aggregate query instead of repeated scans, and model usage avoids double-counting global and per-user counters. Pools now use the configured bounded connection/queue limits in development as well as production and expose graceful shutdown.

## Regression evidence

Focused verification includes `server/workflow.integration.test.ts`, `server/workflow.agent.test.ts`, `server/services/committeeAutoEnroll.test.ts`, `server/services/irb.validation.test.ts`, `server/auth.logout.test.ts`, and the existing `server/irb.test.ts`.

The new workflow integration suite runs only against an explicitly named local test database and cleans up only its own random synthetic fixtures. It checks real MySQL concurrent submission/vote/final-decision/reminder/amendment behavior, stale result rejection, ownership, legacy provenance, unqualified reviewers, private projections, unresolved AI templates and storage key boundaries. The MCP suite uses a real local Express listener with mocked application/storage services to test HTTP envelopes and prevent unauthorized URL issuance. Logout tests cover revocation ordering and failure semantics.

Final focused result: **133 tests passed across 6 files** in 0.950 seconds against the isolated local MySQL test database (34 workflow/MCP/validation tests, 3 logout tests, and 96 existing IRB tests). Staff MFA policy is tested separately by the authentication audit; this focused workflow run deliberately uses the isolated test policy rather than asserting a production MFA enrollment.

## Remaining launch conditions and limitations

1. **Institutional authority is an external fact.** Appointment references are recorded human attestations, not online verification of training, independence, institutional registration or Saudi authorization. The 3-vote full-board / 1-vote expedited-or-exempt floor is a product safeguard, not a determination of statutory quorum, category eligibility, conflicts, required specialties or local SOP compliance. Keep issuance disabled until the responsible qualified institution verifies and activates its actual governance rules. There is no automatic global regulatory validity in 2027.
2. **Legacy decisions require governed reconciliation.** Do not backfill provenance fields merely to make old certificates appear verified. Review original records, responsible humans and legal authority. Existing old signed storage URLs may remain usable until their original expiry or explicit object/key revocation; the code cannot retroactively revoke already issued provider tokens.
3. **Deployment must prove private durable storage and processing geography.** Local permissions do not prove encrypted volumes, backup encryption, retention policy, KSA data residency or restoration capability. S3 encryption is requested but bucket policies, access logs and customer-key arrangements must be checked live. Forge's actual URL expiry/access behavior has not been verified. Validate cloud provider data-processing terms before handling sensitive research information.
4. **Malware scanning integration is implemented; deployment remains an external gate.** User uploads are scanned with a bounded ClamAV INSTREAM TCP client before storage. Production requires a configured scanner by default; missing daemons, malformed replies, socket failures, scan timeouts and ambiguous results fail closed. A FOUND result is rejected. Only the explicit `UPLOAD_SCAN_REQUIRED=false` controlled-pilot policy permits skipping scanning, which is recorded in the upload audit. Configure `CLAMAV_HOST`, optional `CLAMAV_PORT` (3310), `CLAMAV_SCAN_TIMEOUT_MS` (15000; bounded 1000–30000) and `CLAMAV_MAX_CONCURRENT` (4; bounded 1–32). A user can have only one active scan; the global bound limits process resource use. Aborted upload connections cancel active scans. Daemon signature updates, scanning limits (including archive handling), malware-response operations and a real scan drill must be verified before unrestricted public uploads. The TCP daemon must remain on loopback or a protected trusted network: ClamAV TCP provides no authentication or encryption. See the [official protocol specification](https://docs.clamav.net/manual/Usage/ClamdProtocol.html). Metadata/storage failures can leave an unreferenced private object; production still needs lifecycle cleanup and reconciliation.
5. **Operational workflows need real staffing and drills.** Confirm adverse-event escalation ownership, response SLAs, conflict adjudication, continuing-review schedules, amendment implementation and reviewer replacement under the institution's SOP. Reminder deduplication is implemented; actual scheduled invocation and delivery are a separate deployment fact. Full human-led clinical and regulatory acceptance testing remains required.
6. **At scale:** transactional correctness was exercised with concurrent local requests; this is not proof of regional failover, production throughput, sustained object storage capacity, managed MySQL replica behavior or real provider latency. Most staff listing endpoints still return full authorized collections, so benchmark realistic data volume and add cursor pagination as needed before large institutional onboarding.

## Additional malware-scanner verification

The scanner was checked against the official ClamAV protocol documentation. A local fake TCP daemon verified exact multi-chunk framing, split clean replies, FOUND rejection, malformed/truncated/oversized responses, timeouts, socket resets, cancellation, global capacity recovery and production policy enforcement. Router tests verify that denied/cancelled scans never reach storage or metadata and that successful scans precede storage. **21 tests passed across the two new scanner test files**, including a regression run after adding the per-user capacity guard. TypeScript verification also passed. This is protocol/integration evidence, not a claim that a production daemon or signature-update service is deployed.

## Encrypted backup and restore drill

`scripts/backup.sh` and `scripts/restore.sh` now use private temporary directories and `umask 077`, never load `.env`, reject malformed database URLs and control characters, and require verified TLS with `BACKUP_DB_SSL_CA` for remote connections. Backups require `BACKUP_GPG_RECIPIENT` or `BACKUP_PASSPHRASE` of at least 20 characters. `ALLOW_UNENCRYPTED_BACKUP=true` is an explicit exception for isolated tests. Passphrase archives use authenticated AES-256-GCM with a random salt/IV, PBKDF2-SHA256 at 600,000 iterations, and an authenticated format header. Every archive has a SHA-256 sidecar. Failed dump/encryption operations remove temporary plaintext.

Restore requires `RESTORE_CONFIRM_DB` to equal the exact existing target database name. The former `CONFIRM=yes` authorization is rejected. Archive bytes are copied into a private workspace, then checksum, full authenticated decryption, gzip integrity and complete decompression finish before any database write. Database-switching directives are rejected, and local infile import is disabled. Restore must still use a trusted archive and a database account restricted to the intended target: a SQL dump is executable SQL, and the directive check is not a complete SQL sandbox. The new `.sql.gz.enc` format intentionally does not accept legacy unauthenticated OpenSSL CBC archives; review and migrate those separately in isolation.

An actual encrypted backup from the local synthetic `irb_readiness_test` database was restored to the newly created local `irb_restore_test` database with native MySQL 9.6. All 20 tables were restored. Every archived INSERT statement matched a fresh dump of the restored database, including all 10 populated tables. A later live-source comparison matched 19 of 20 tables; the source's active rate-limit expiry changed `request_limits` after the snapshot. The receipt records both results explicitly rather than misrepresenting a changing source as a frozen snapshot.

**All 19 negative checks passed**, covering checksum tampering, ciphertext tampering with a recomputed checksum, wrong passphrase, incorrect/missing target confirmation, URL injection, unsafe remote TLS, required encryption, weak passphrases, failed-dump plaintext cleanup, authenticated invalid gzip, database-switching SQL, unchanged target data across failed restores, archive permissions and temporary-file cleanup. Evidence is in [backup-restore-20260905.json](verification/backup-restore-20260905.json). This drill did not access production data, run source-database DDL, upload to S3, or validate live GPG, managed database TLS, offsite retention or disaster recovery objectives. Operators must complete those deployment-specific checks.
